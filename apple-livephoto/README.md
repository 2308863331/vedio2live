# 视频 → iPhone 实况照片（Live Photo）转换工具

把一段普通视频变成 iPhone 能认的实况照片：一张封面照 `.jpg` + 一段视频 `.mov`。

- 只用 macOS 自带的 AVFoundation / ImageIO，**不需要 ffmpeg、exiftool、Homebrew**
- 编译一次，之后离线可用，不上传任何东西
- 一次可以出多张（`--at 5,12.5,30`）

---

## 一、先编译（只做一次）

```bash
cd apple-livephoto
bash build.sh
```

看到 `编译完成` 就成了，可执行文件在 `bin/` 里。

## 二、怎么用

### 最简单：整段视频做成一张实况照片

```bash
./livephoto.sh 我的视频.mp4
```

不裁剪，视频多长实况照片就多长。封面用第一帧。

### 只想截一段

```bash
./livephoto.sh 我的视频.mp4 12.5        # 第 12.5 秒做封面，取 3 秒
./livephoto.sh 我的视频.mp4 12.5 8      # 第 12.5 秒做封面，取 8 秒
```

片段以你说的那个时刻为中心，向前后各取一半。

### 一次做多张

```bash
./livephoto.sh 我的视频.mp4 5,12.5,30 10
```

出 3 组（每组 10 秒），封面分别在第 5、12.5、30 秒。

### 结果在哪

都在 `apple-livephoto/实况图/` 里：

```
我的视频.jpg     封面照
我的视频.mov     视频部分
```

多张时依次是 `我的视频_1.jpg / 我的视频_1.mov / 我的视频_2.jpg ...`

`.jpg` 和 `.mov` 是**一对**：里面写着同一个编号（UUID），iPhone 靠这个编号把它们认成一张实况照片。所以**拷的时候必须两个一起拷，也不能和别的组混**。

## 三、拷进 iPhone

把成对的 `.jpg` 和 `.mov` 一起 AirDrop 到 iPhone（或存进「照片」），打开照片长按，会动。

如果不动，多半是这两个文件没被同时识别成一对，重拷一次即可。

## 四、时长这件事，说实话

**文件本身没有时长上限。** 10 秒、30 秒、60 秒都能做出来，工具也不会自己截断（自检里专门验了 10 秒不被砍成 3 秒）。

真正的限制不在文件，在**用来干什么**：

| 用途 | 实际限制 |
|---|---|
| 锁屏动态壁纸 | 约 2 秒（iOS 只播开头那段） |
| 发朋友圈 / 小红书 | 上限**待实测**，工具不替平台打保票 |
| 极长视频（比如 10 分钟） | 文件能生成，但**在 iOS 相册、微信、小红书里能不能正常识别和播放，需要在真机上实测**，工具不保证 |

想当动态壁纸就做 2 秒；想发社交平台建议先做一版 3～5 秒试发，确认平台收不收再批量做长的。

## 五、自检（想确认工具没坏就跑这个）

```bash
bash verify.sh
```

它会真的编译、真的生成测试视频、真的转一遍，然后**逐项打印数字**：输出时长和源时长对比、JPG 和 MOV 的编号是否相同、MOV 里有没有 `still-image-time` 元数据轨、竖屏有没有被转成横屏、定格补长的画面是不是黑帧。每项前面会写 `[通过]` 或 `[不通过]`，有失败项退出码非 0。

自检脚本会去找一个名为 `sample.mp4` 的真实视频（路径写死在 `verify.sh` 里）来验整段模式。**这个文件不随仓库提供**：请自备一个任意 H.264+AAC 的 mp4 放到脚本里写的那条路径；没有它自检也不会失败，会自动改用自己合成的 20 秒测试片跑。

## 六、完整参数（给愿意敲命令的人）

```bash
bin/video2livephoto --video <输入视频> --out <输出目录> \
                    [--at <秒>[,<秒>...]] [--duration <秒>] \
                    [--name <文件名前缀>] [--width <像素>]
```

| 参数 | 说明 |
|---|---|
| `--video` | 输入视频（mp4 / mov / m4v） |
| `--out` | 输出目录，不存在会自动建 |
| `--at` | 封面时刻（秒），逗号分隔多个就出多组。整段模式下默认 0（第一帧）；裁剪模式下不传则取视频中点 |
| `--duration` | 要裁多长（秒）。**不传 = 整段不裁剪**。没有上限 |
| `--name` | 输出文件名前缀，默认取视频文件名 |
| `--width` | 输出宽度（像素）。不传则保持原分辨率（最长边不超过 1920）且**直通复制不重编码** |
| `--photo-format` | 封面格式：`jpg`（默认，不传就是这个）或 `heic`。heic 给 `.livp` 打包用 |

另外三个查看类命令：

```bash
bin/video2livephoto --probe 视频.mp4                   # 看时长、分辨率、有没有音轨
bin/video2livephoto --inspect 封面.jpg 视频.mov          # 检查这一对配得对不对（heic 封面也认）
bin/video2livephoto --grab 视频.mov 3 out.jpg           # 抽第 3 秒那一帧看画面
```

## 六之二、HEIC 封面 和 .livp 单文件（Plan B）

AirDrop 两个散文件过去如果 iPhone 不认，用这两步改成单文件 `.livp`。

### 第一步：出 HEIC 封面

```bash
bin/video2livephoto --video 我的视频.mp4 --out 实况图 --photo-format heic
```

多一个参数 `--photo-format heic`，封面就从 `.jpg` 变成 `.heic`。**不传这个参数，行为和以前完全一样（还是 `.jpg`）。**
HEIC 里同样写了 Apple maker note key 17，和 `.mov` 的编号一致。

### 第二步：打成 .livp

```bash
./makelivp.sh 实况图/我的视频.heic 实况图/我的视频.mov 我的视频.livp
```

`.livp` 是一个 ZIP，里面装一个图 + 一个 mov。**真正让它被认出来的不是 ZIP 本身，而是 ZIP 注释里那段定位串**
（`0002` + 图片数据的字节偏移和大小 + `0003` + 视频数据的字节偏移和大小 + `1000LIVP`）——
导入流程不按文件名找文件，而是读注释直接切字节。所以注释里的数字错一个字符，文件就废了。

### 第三步：验一遍（建议每次都跑）

```bash
python3 verify-livp.py 我的视频.livp
```

它真的把 `.livp` 拆开读：按 `50 4B 03 04` 遍历条目、把注释按规则重建一遍逐字符比对、
再用注释里的偏移去切字节确认切出来的确实是那个文件，最后把注释末尾那串 hex 解成 `1000LIVP` 打出来。
全项通过退出码 0，有任一不通过退出码 1。

如果 `.livp` 拷进 iPhone 认不出来，可以先试一步保险：把包内条目名换成纯 ASCII 的 `image.heic` / `video.mov`，再打一个包试：

```bash
python3 makelivp.py 实况图/我的视频.heic 实况图/我的视频.mov 我的视频-ascii.livp --ascii-names
```

（中文条目名会让 ZIP 带上 UTF-8 标志位，万一某个导入实现按老编码读名字会读成乱码；扩展名本身是 ASCII，一般不影响识别。）

## 七、速度与画质

- **不传 `--width` 时是直通复制**：视频数据原样搬过去，画质零损失。197 秒、13 MB 的视频约 15 秒转完
- 传了 `--width` 才重新编码（要缩放就必须解码再编码）
- 源片比 `--duration` 短时，用首尾帧定格把片子撑到你要的时长（这一步必须重编码）

## 八、转出来的文件里有什么

- `.mov`：H.264 视频 + 原声（源片有音频就带上），`moov` 前置（等价 `+faststart`），手机不用下完整个文件就能播
- `.mov` 里有一条 `still-image-time` 定时元数据轨，标出哪一帧是封面
- `.jpg`：封面帧，Apple maker note 里的 key `17` 写的就是那个编号
- `.mov` 和 `.jpg` 共用同一个编号（UUID）—— 这是 iOS 认定它们是同一张实况照片的依据

## 九、已知限制

- 只认 macOS 自带解码器支持、且有**视频轨**的文件；纯音频文件会直接报错退出
- 输出默认是 `.mov` + `.jpg` 两个文件，需要单文件时用 `makelivp.sh` 打成 `.livp`
- 微信 / 小红书对实况照片的支持时常变化，工具只保证文件格式正确
- `.livp` 能不能被 iPhone「照片」认成实况照片，**还没做真机实测**；本机只验证了文件的字节结构符合导入流程的读法
