# 视频 → 安卓实况照片（Motion Photo）

把一个普通视频，做成**一张手机上能当「实况照片」看的 JPG**：图是封面，动的是里面的视频。

## 先说清楚：这跟苹果的实况照片不是一回事

| | 苹果 Live Photo | 安卓 Motion Photo（**这个工具做的**） |
|---|---|---|
| 产物 | **两个文件**：照片 + `.mov` | **一个文件**：`.jpg` |
| 怎么配对 | 靠 UUID 把两个文件绑在一起 | 视频直接接在 JPG 的末尾，JPG 里写了「视频在哪儿、多长」 |
| 谁认 | 苹果手机 / 苹果相册 | 安卓手机 |
| 互通吗 | **不互通。** 苹果手机、苹果相册**不认**这个工具做出来的文件 | 反过来也一样 |

苹果那套已经有一个工具了（`apple-livephoto/`），跟这个不是一个东西，别混用。

## 怎么用

**第 0 步：先把取封面帧要用的工具编出来（只做一次）。**
这版借用 `apple-livephoto/` 里的抽帧工具来抓封面，所以要先编译它（仓库不带编译好的二进制）：

```bash
cd apple-livephoto && bash build.sh && cd ..
```

如果跳过这一步，运行时会报「找不到抽帧工具 `apple-livephoto/bin/video2livephoto`」。

**第 1 步：生成**

```bash
cd android-motionphoto

# 一行搞定（推荐）
./make-motionphoto.sh ~/Downloads/sample.mp4 sample.jpg --at 12.5

# 或者分两步
python3 motionphoto.py --video ~/Downloads/sample.mp4 --out sample.jpg --at 12.5
python3 verify-motionphoto.py sample.jpg --source ~/Downloads/sample.mp4
```

不想编译苹果那套工具的话，也可以用 `--image` 直接指定一张现成的封面图，绕过抽帧（详见 `motionphoto.py --help`）。

- `--at 12.5` = 封面取视频第 12.5 秒那一帧。不写就是第 0 秒。
- **视频默认整段嵌进去，不裁剪。** 视频多长，实况就多长。
- 第一次跑会自动编译一个小的 Swift 工具（约 1 分钟）。

跑完会打印一堆数字（文件多大、视频从第几个字节开始、时长多少），然后自动校验一遍。
**校验最后一行写着「退出码 0」才算好**；写着「退出码 1」就是有问题，它会说清是哪一项。

> 上面命令和 `test-mutations.py` 里提到的 `sample.mp4` 只是个示例名字，**仓库不提供这个文件**。请自备一个任意 H.264+AAC 的 mp4 当输入视频，换成你自己的文件名即可。

## 产物是什么

就是一个 **`.jpg` 文件**，里面有：

1. 一张普通 JPEG 封面（能被任何看图软件打开，就是一张照片）
2. 封面后面紧跟着一整段 MP4 视频
3. JPEG 里写了一小段说明（XMP），告诉手机「视频从这个文件的倒数第多少字节开始、有多少字节、封面是第几秒」

文件大小 ≈ 封面大小 + 视频大小。比如拿 197 秒的 `sample.mp4`（13.4 MB）做出来是 13.6 MB。

## 文件都是干什么的

| 文件 | 作用 |
|---|---|
| `make-motionphoto.sh` | 给人用的一行命令，生成 + 校验 |
| `motionphoto.py` | 组装器：JPEG + MP4 → 一个文件 |
| `verify-motionphoto.py` | 校验器：真去解析产物，逐项打印，有问题退出码 1 |
| `remux-faststart.swift` | 把视频改成「头朝前」的 MP4（看图软件从中间开始播不会卡），不重新编码 |
| `build.sh` | 编译上面那个 Swift 工具到 `bin/` |
| `test-mutations.py` | 反向验证：故意把产物改坏，确认校验脚本真会报错 |
| `.tmp/` | 中间文件（抽出来的封面、转好的 MP4、校验时切出来的视频），可随时删 |
| `.build-cache/` | 编译 Swift 用的缓存，删了也行，只是下次编译慢一次（第一次约 1 分钟） |

## 哪些事没验证过（**重要，别当成已经能用**）

1. **本机没有安卓手机，一次都没在真机上试过。**
   微信、小红书、OPPO / vivo / 荣耀 / 小米相册**认不认这个文件，完全没测**。
2. **本机验的只是「字节结构符合公开格式规范」** —— JPEG 是完整的、视频在 EOI 后面、XMP 字段齐全、长度和偏移前后算得一致、视频时长没被裁。
   **这不等于手机上一定认。**
3. 具体没验的：
   - 197 秒这种**很长的**实况照片，安卓手机播不播得动、要不要等很久
   - 微信 / 小红书**收不收桌面电脑生成的文件**（它们可能只认手机拍的）
   - 封面时间戳（`--at`）在手机上跳转的位置对不对
   - 视频里是竖屏 / 横屏、有没有旋转标记时的显示方向
   - 没有音轨的视频、有多个视频轨的视频
   - 超过 2 GB 的文件
4. **苹果手机、苹果相册不认这个文件**（格式就不是一套，见上表）。

建议：拿到安卓手机上先试一张，试通了再批量做。
